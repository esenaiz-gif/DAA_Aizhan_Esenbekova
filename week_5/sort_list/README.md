# Problem 2: Sort List (LeetCode)

## 1. Problem (Описание задачи)
Требуется отсортировать односвязный список, заданный своим головным узлом (`head`), в порядке возрастания. Главная сложность задачи заключается в необходимости выполнения алгоритма за время $O(n \log n)$ с минимальными затратами дополнительной памяти, учитывая особенности структуры связных списков, которые не поддерживают прямой доступ к элементам по индексу.

---

## 2. Approach (Подход и разбор кода по строчкам)
Поскольку традиционные методы сортировки с произвольным доступом неэффективны для связных списков, была реализована **Сортировка слиянием для связных списков (Merge Sort for Linked Lists)**.

### Построчный разбор кода (`SortList.java`):

1. **`public ListNode sortList(ListNode head)`** — Основной публичный метод. Сначала проверяется базовый случай (`if (head == null || head.next == null)`): если список пустой или содержит только один узел, он уже отсортирован и возвращается без изменений.
2. **Поиск середины списка (Fast & Slow pointers):**
    * Инициализируются три указателя: `ListNode prev = null;`, `ListNode slow = head;`, `ListNode fast = head;`.
    * В цикле `while (fast != null && fast.next != null)` указатель `fast` смещается на два шага, а `slow` — на один. Когда `fast` достигает конца, `slow` оказывается ровно в середине списка.
3. **`prev.next = null;`** — Связь между первой и второй половинами разрывается, разделяя единый список на два независимых подсписка.
4. **Рекурсивное разделение:**
    * `ListNode l1 = sortList(head);` — Рекурсивно сортируется левая часть.
    * `ListNode l2 = sortList(slow);` — Рекурсивно сортируется правая часть.
5. **`return merge(l1, l2);`** — Вызывается вспомогательная функция слияния двух отсортированных списков.
6. **`private ListNode merge(ListNode l1, ListNode l2)`** — Функция слияния:
    * Создается вспо фиктивный узел (`dummyHead`), упрощающий работу со ссылками.
    * В цикле `while (l1 != null && l2 != null)` узлы сравниваются по значению (`l1.val <= l2.val`), и меньший последовательно присоединяется к результирующему списку.
    * Оставшиеся узлы (если таковые остались в одном из списков) присоединяются в конец.
    * Возвращается `dummyHead.next`, представляющий голову объединенного отсортированного списка.

### Трассировка (Пример по шагам):
Пусть задан список `4 -> 2 -> 1 -> 3`.
1. **Поиск середины и разделение:**
    * Метод быстрых/медленных указателей останавливает `slow` на значении `1`.
    * Список разделяется на две части: `4 -> 2` и `1 -> 3`.
2. **Рекурсивная сортировка половин:**
    * Левая часть `4 -> 2` делится на `4` и `2`, после слияния образует `2 -> 4`.
    * Правая часть `1 -> 3` делится на `1` и `3`, после слияния образует `1 -> 3`.
3. **Финальное слияние (`merge`):**
    * Сравниваются узлы `2` и `1` $\rightarrow$ выбирается `1`.
    * Сравниваются узлы `2` и `3` $\rightarrow$ выбирается `2`.
    * Сравниваются узлы `4` и `3` $\rightarrow$ выбирается `3`.
    * Дописывается оставшийся узел `4`.
    * **Итоговый результат:** `1 -> 2 -> 3 -> 4`.

### Трудности, возникшие при реализации:
На ранних этапах рассматривался подход с временным копированием значений узлов в массив, их последующей сортировкой и перезаписью обратно в список. Данный подход работает, однако он увеличивает накладные расходы по памяти и не соответствует концепции эффективного манипулирования указателями. Основной сложностью при реализации честного разделения списка через указатели был корректный разрыв связей (`prev.next = null`), позволяющий избежать зацикливания рекурсии.

## 3. Time and Space Complexity (Временная и пространственная сложность)
* **Time Complexity (Временная сложность): $O(n \log n)$**
    * *Обоснование:* Разделение связного списка пополам происходит за $\log n$ уровней рекурсии, а процедура слияния двух списков на каждом уровне линейно зависит от общего числа узлов $O(n)$. Итоговая сложность составляет $O(n \log n)$.
* **Space Complexity (Пространственная сложность): $O(\log n)$**
    * *Обоснование:* Дополнительные структуры данных (вроде массивов) не создаются, однако рекурсивные вызовы функции `sortList` занимают память в стеке вызовов, глубина которого пропорциональна $\log n$.

---

## 4. Reflection / Improvement (Рефлексия и возможные улучшения)
* **Существует ли более эффективный подход?** Да, итеративная модификация сортировки слиянием (Bottom-Up Merge Sort).
* **Что для этого потребуется изменить?** Вместо рекурсивного разделения сверху вниз следует реализовать итеративный проход по списку с увеличивающимся размером шага слияния (1, 2, 4 и т. д.), управляя указателями в циклах.
* **Каких показателей сложности можно достичь?** Временная сложность останется прежней — $O(n \log n)$, но пространственная сложность снизится до идеального константного уровня **$O(1)$**, поскольку глубина стека рекурсии будет полностью исключена.
