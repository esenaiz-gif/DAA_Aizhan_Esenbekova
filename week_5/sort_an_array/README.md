# Problem 1: Sort an Array (LeetCode)

## 1. Problem (Описание задачи)
Требуется отсортировать заданный массив целых чисел `nums` в порядке возрастания. Решение должно удовлетворять ограничению по времени выполнения $O(n \log n)$ и эффективно обрабатывать большие объемы входных данных.

---

## 2. Approach (Подход и разбор кода по строчкам)
В данном решении используется алгоритм **Сортировки слиянием (Merge Sort)**, основанный на парадигме «разделяй и властвуй». Исходный массив рекурсивно делится на подмассивы до тех пор, пока каждый из них не будет состоять из одного элемента, после чего происходит их слияние в отсортированном порядке.

### Построчный разбор кода (`SortAnArray.java`):

1. **`public int[] sortArray(int[] nums)`** — Основной публичный метод. Сначала выполняется проверка на базовые случаи (`if (nums == null || nums.length <= 1)`): если массив пуст или содержит один элемент, он возвращается без изменений.
2. **`int[] temp = new int[nums.length];`** — Инициализируется вспомогательный массив `temp` аналогичного размера для временного хранения элементов в процессе слияния.
3. **`mergeSort(nums, 0, nums.length - 1, temp);`** — Вызывается рекурсивная вспомогательная функция `mergeSort` для сортировки всего диапазона элементов массива.
4. **`private void mergeSort(...)`** — Функция деления:
    * Вычисляется индекс середины диапазона: `int mid = left + (right - left) / 2;`
    * Рекурсивно обрабатывается левая половина (`mergeSort(nums, left, mid, temp)`) и правая половина (`mergeSort(nums, mid + 1, right, temp)`).
5. **`private void merge(...)`** — Функция слияния двух отсортированных частей:
    * Элементы текущего диапазона копируются во временный массив `temp`.
    * Используются три указателя: `i` (для левой части), `j` (для правой части) и `k` (для записи обратно в исходный массив `nums`).
    * На каждом шаге меньший из элементов (`temp[i]` или `temp[j]`) помещается в исходный массив `nums[k]`.
    * В завершение оставшиеся элементы из левой или правой части переносятся в результирующий массив.

### Трассировка (Пример по шагам):
Пусть входной массив равен `[4, 1, 3, 2]`.
1. **Деление (Divide):**
    * Массив разделяется на две половины: `[4, 1]` и `[3, 2]`.
    * Каждая половина делится дальше на одиночные элементы: `[4]`, `[1]`, `[3]`, `[2]`.
2. **Слияние (Merge):**
    * Сливаются пары `[4]` и `[1]` $\rightarrow$ получается `[1, 4]`.
    * Сливаются пары `[3]` и `[2]` $\rightarrow$ получается `[2, 3]`.
    * Сливаются подмассивы `[1, 4]` и `[2, 3]`:
        * Сравнение `1` и `2` $\rightarrow$ выбирается `1`.
        * Сравнение `4` и `2` $\rightarrow$ выбирается `2`.
        * Сравнение `4` и `3` $\rightarrow$ выбирается `3`.
        * Записывается оставшийся элемент `4`.
    * **Итоговый результат:** `[1, 2, 3, 4]`.

### Трудности, возникшие при реализации:
На начальном этапе тестировался более простой алгоритм сортировки пузырьком (Bubble Sort). Однако на больших тестах он приводил к ошибке **Time Limit Exceeded** из-за квадратичной временной сложности $O(n^2)$. Переход на сортировку слиянием позволил устранить эту проблему производительность, однако потребовал внимательного контроля за индексами и корректным использованием вспомогательного массива для предотвращения выхода за границы памяти.

## 3. Time and Space Complexity (Временная и пространственная сложность)
* **Time Complexity (Временная сложность): $O(n \log n)$**
    * *Обоснование:* Глубина рекурсивного разделения массива составляет $\log n$ уровней, а на каждом уровне для слияния элементов требуется линейный проход за $O(n)$ операций. Общая сложность определяется как произведение количества уровней на объем работы на каждом уровне.
* **Space Complexity (Пространственная сложность): $O(n)$**
    * *Обоснование:* Дополнительная память расходуется на создание вспомогательного массива `temp` размера $n$ ($O(n)$) и стек вызовов рекурсии глубиной $O(\log n)$. Доминирующим фактором является линейная память $O(n)$.

---

## 4. Reflection / Improvement (Рефлексия и возможные улучшения)
* **Существует ли более эффективный подход?** Да, алгоритмы вроде HeapSort (пирамидальная сортировка) могут обеспечивать аналогичную временную сложность $O(n \log n)$.
* **Что для этого потребуется изменить?** Необходимо отказаться от выделения дополнительной памяти под временный массив и реализовать сортировку непосредственно внутри исходного массива (in-place).
* **Каких показателей сложности можно достичь?** Время выполнения останется на уровне $O(n \log n)$, но пространственная сложность снизится до константной $O(1)$. Тем не менее, Merge Sort сохраняет преимущество в виде стабильности сортировки.
