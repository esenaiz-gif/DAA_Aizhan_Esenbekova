# Task 1: Merge Two Sorted Arrays

## 1. Problem (Описание проблемы)
Необходимо объединить два отдельных массива, которые уже отсортированы по возрастанию, в один общий отсортированный массив. Задача решается без использования указателей связных списков, применяя классическую логику слияния двух отсортированных последовательностей (аналогично этапу `merge` в алгоритме Merge Sort из материалов курса).

## 2. Approach (Подход и трассировка)
Для решения используется **подход с тремя индексами (указателями)**:
* `i` — текущая позиция в результирующем массиве `result`.
* `l` — текущий индекс в первом массиве `left`.
* `r` — текущий индекс во втором массиве `right`.

**Алгоритм работы:**
1. Создается массив `result` размером, равным сумме длин `left` и `right`.
2. В цикле пока не исчерпан один из массивов, мы сравниваем элементы `left[l]` и `right[r]`. Меньший элемент записывается в `result[i]`, после чего соответствующий индекс (`l` или `r`) и индекс `i` увеличиваются на 1.
3. После завершения цикла оставшиеся элементы неизрасходованного массива просто дописываются в хвост `result`.

#### Пример трассировки:
* `left = [-5, 1, 3]`, `right = [-3, 2]`
* **Шаг 1**: Сравниваем `-5` (`left[0]`) и `-3` (`right[0]`). `-5 < -3` $\rightarrow$ записываем `-5`. `l = 1`, `i = 1`.
* **Шаг 2**: Сравниваем `1` (`left[1]`) и `-3` (`right[0]`). `-3` меньше $\rightarrow$ записываем `-3`. `r = 1`, `i = 2`.
* **Шаг 3**: Сравниваем `1` (`left[1]`) и `2` (`right[1]`). `1` меньше $\rightarrow$ записываем `1`. `l = 2`, `i = 3`.
* **Шаг 4**: Сравниваем `3` (`left[2]`) и `2` (`right[1]`). `2` меньше $\rightarrow$ записываем `2`. `r` достигает конца (`2`), цикл прекращается.
* **Остаток**: Дописываем оставшийся элемент `3` из `left`.
* **Результат**: `[-5, -3, 1, 2, 3]`.

## 3. Complexity (Анализ сложности)
* **Time Complexity (Временная сложность):** $O(n + m)$
    * *Объяснение:* Где $n$ и $m$ — длины массивов `left` и `right`. Каждый элемент из обоих массивов посещается и записывается ровно один раз.
* **Space Complexity (Пространственная сложность):** $O(n + m)$
    * *Объяснение:* Для сохранения результата выделяется дополнительный массив размером $n + m$.

## 4. Reflection / Improvement (Рефлексия)
* **Существует ли более эффективный подход?** Асимптотически улучшить время нельзя, так как нужно просмотреть каждый элемент. Сделать слияние «на месте» (in-place) без дополнительной памяти для массивов без потери эффективности невозможно ($O(n \times m)$ в худшем случае при сдвигах). Выделение памяти $O(n + m)$ является оптимальным.
