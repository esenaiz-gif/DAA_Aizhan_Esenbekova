# Binary Search

## 1. Problem
Дан отсортированный массив целых чисел `nums` и число `target` (цель). Нам нужно написать функцию для поиска индекса этого числа в массиве. Если число существует, вернуть его индекс, в противном случае вернуть `-1`. Поиск должен быть максимально эффективным за счет деления области поиска пополам.

## 2. Approach
Для решения этой задачи я использовала классический алгоритм **бинарного поиска (Binary Search)**. Поскольку массив уже отсортирован, нам не нужно проверять каждый элемент по порядку. 

Ниже подробно описано, как работает каждая строка и каждый блок моего кода:

- `public static int binarySearch(int[] nums, int target)`: Основной метод, принимающий отсортированный массив и искомое число.
  - `int left = 0;` и `int right = nums.length - 1;` — задаем начальные границы поиска. `left` указывает на самый первый элемент (индекс 0), а `right` — на самый последний.
  - `while (left <= right)` — цикл работает до тех пор, пока левая граница не перешагнет правую.
  - `int mid = left + (right - left) / 2;` — находим индекс середины текущего диапазона. Такая формула защищает от переполнения памяти при больших массивах.
  - `if (nums[mid] == target) { return mid; }` — проверяем, не оказался ли элемент посередине тем, что мы ищем. Если да, сразу возвращаем его индекс.
  - `else if (nums[mid] < target) { left = mid + 1; }` — если число в середине *меньше* искомого, значит, наше число гарантированно лежит в правой половине. Сдвигаем левую границу (`left = mid + 1`).
  - `else { right = mid - 1; }` — если число в середине *больше* искомого, значит, нужно искать в левой половине. Сдвигаем правую границу (`right = mid - 1`).
- `return -1;` — если цикл завершился, а число так и не нашлось, возвращаем `-1`.
- `public static void main(String[] args)` — главный метод для проверки. В нем задан тестовый массив, искомое число `23`, запускается алгоритм и выводится результат в консоль.

## 3. Time Complexity
**Time Complexity:** O(log n)

**Explanation:** На каждой итерации цикла алгоритм делит область поиска ровно пополам, отсекая 50% элементов. В худшем случае количество проверок пропорционально логарифму по основанию 2 от количества элементов `n`. Поэтому временная сложность составляет O(log n).

## 4. Space Complexity
**Space Complexity:** O(1)

**Explanation:** Алгоритм использует только несколько вспомогательных целочисленных переменных (`left`, `right`, `mid`), объем которых фиксирован и не зависит от размера входящего массива. Дополнительная память не выделяется, поэтому пространственная сложность равна O(1).

## 5. Reflection / Improvement
- **Is there a more efficient approach?** Нет, для поиска в отсортированном массиве бинарный поиск с O(log n) является математически оптимальным. Линейный поиск проверял бы каждый элемент за O(n) времени, что гораздо медленнее.
- **What would you need to change?** Менять алгоритм не требуется, текущая итеративная реализация работает идеально и эффективно.
- **What complexity could the improved solution achieve?** O(log n) времени и O(1) дополнительной памяти.
